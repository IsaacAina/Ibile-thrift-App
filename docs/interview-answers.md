In two layers. Primitives hold raw values, like the colour palette and the type scale. Roles are semantic names like action-primary or text-primary that alias the primitives. UI code uses roles only, and a script generates the CSS from one JSON file.
When it changes a token’s name, removes it, or changes its meaning so that existing uses break. Changing a value is usually safe. Renaming a token or changing what it is for is not, so I treat those as a major version.
Brands swap the primitive palette. Themes (light and dark) swap which primitive each role points to. Components never change because they only use roles.
No. Tokens can define approved text and background pairings, but they can’t stop someone from using a bad pair. Contrast has to be tested.
I check pairs in design with a contrast tool (Figma plugin) and build only approved pairs into the roles. The targets are 4.5:1 for normal text and 3:1 for large text and UI elements.
A is the bare minimum, where missing it blocks users completely. AA is the standard target for most products and legal requirements (4.5:1 contrast). AAA is the strictest (7:1 contrast), and it isn’t always achievable for a whole site, so I apply it where possible.
Elements like button, nav, main and h1 to h6 tell browsers and screen readers what things are. They give keyboard support, focus behaviour and landmarks for free. A div pretending to be a button has none of that unless I rebuild it myself.
I name Figma variables to match the code tokens, use components with every state defined (hover, focus, disabled, error), and use Dev Mode and annotations for spacing and behaviour. I also export tokens as JSON, so design and code share one source.
Models produce the average of what they’ve seen: default fonts, purple gradients, evenly spaced cards. I hand the agent the token file, a role-only rule, the type scale, spacing rules, an instruction to flag gaps instead of improvising, and a check script that rejects raw values.
My Display Large line height is 64px because large type needs tighter spacing than body text. One step tighter and lines start to collide, especially with descenders and wrapped headings. One step looser and the heading looks like separate lines rather than one block, and it wastes vertical space.
My primitives are named primary-N, which ties the palette name to a role. Next time I’d name them by hue (blue-600), so a rebrand doesn’t leave a name like primary holding purple. The cost is a one-time rename and an extra mapping step.
Exporting hex values into one CSS file is only a central list of values. It has no meaning layer: nothing says which blue is for buttons and which is for links. It also has no enforcement, so developers can still type a hex. In month four, someone rebrands or adds dark mode and finds raw values scattered through the code and no way to change the intent in one place. The Figma export is also a one-time copy, so design and code drift apart. A real single source of truth needs roles that reference primitives, one generated output, and checks that block hardcoded values.
